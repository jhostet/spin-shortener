## Priority Issues

**[P1] "Custom" badge violates the system's own accent-color rule and fails contrast**
- **Why it matters**: DESIGN.md states Signal Blue "appears only as a hover accent, never a resting fill" outside nav/buttons/links — the new badge uses it as a permanent resting color, a checkable violation of the project's own documented rule, and computes to ~4.15:1 contrast against white (below the 4.5:1 AA minimum for this text size/weight).
- **Fix**: Recolor `.slug-kind-badge` to a neutral tone (matching `.lock-badge`'s already-correct slate-muted treatment) and re-verify contrast.
- **Suggested command**: `/impeccable harden`

**[P1] "Expiring soon" only covers the future half of the problem — already-expired links look identical to healthy ones**
- **Why it matters**: `status` is a manual toggle independent of the time window, so a lapsed campaign link can sit in the table reading "Status: active" with zero visual indication it's already 404-ing on every click — directly undermining the marketing persona's core need to track live vs. dead scheduled links, the exact need this feature was added for.
- **Fix**: Add a distinct "(expired)" treatment whenever `end_at` is in the past, independent of the 24h look-ahead.
- **Suggested command**: `/impeccable clarify`

**[P1] Combined edit save can partially succeed with no disclosure**
- **Why it matters**: Save first PATCHes URL/window, then separately POSTs password; if the PATCH succeeds and the password call fails, the shown error gives no indication the URL/window half already committed — a real visibility-of-status regression this pass introduced.
- **Fix**: Distinguish "Destination/window saved; password change failed: <reason>" from a full failure, or re-render the row's actual current values immediately.
- **Suggested command**: `/impeccable harden`

**[P2] Sortable table headers are mouse-only**
- **Why it matters**: No `tabindex`, no keyboard handler, no `aria-sort` on the sortable headers — a keyboard-only or screen-reader user cannot sort the busiest table in the app at all.
- **Fix**: Make each header a real focusable control with Enter/Space handling and `aria-sort` reflecting current state.
- **Suggested command**: `/impeccable harden`

**[P2] "Custom slug" terminology drift on the detail page**
- **Why it matters**: `links/detail.html` labels the field "Custom slug:" while the rest of the app calls the same concept "custom short link" — technical jargon leaking in on exactly the page this pass just touched, in front of a non-technical persona.
- **Fix**: Rename to "Custom short link:" to match the rest of the app.
- **Suggested command**: `/impeccable clarify`

## Persona Red Flags

**Alex (Power User)**: sort headers can't be reached via Tab, let alone triggered by key. No bulk actions anywhere. The new combined edit row is slower for the common single-field-typo-fix case — six fields to scan to change one.

**Sam (Accessibility-dependent)**: cannot operate the sort at all via keyboard/screen reader. The "Custom" badge fails WCAG AA contrast. Edit-row inputs live outside any `<form>`, so native validation UI (which a screen reader announces) never fires.

**Morgan (Campaign Marketer, project-specific)**: a two-week promo link, two weeks later, still reads "Status: active" with a plain Expires date and zero visual cue it's already lapsed — the exact working-memory burden "expiring soon" was meant to remove, just for the other half of the timeline. Sees "Custom slug" on the detail page after filling in "custom short link" on the dashboard — a small "did I break something?" moment. If a password typo fails alongside a URL fix in one Save, she can't tell which half landed.

## Minor Observations

- The new `caption` token (0.75rem/600-weight) is only half-applied to the compact action-button group — it carries the font-size but not the documented font-weight, an inconsistency worth a deliberate decision.
- Native `confirm()` for delete is functionally fine but visually foreign to the app's styled system at the one moment (irreversible delete) where tone matters most.
- No loading/disabled state on any button during an in-flight fetch — double-submit risk on a slow connection.
- Help/documentation remains effectively zero in-app — acceptable for a small internal tool, but worth a deliberate decision rather than default omission (e.g., permission-checkbox meanings on admin/users.html are never explained in-page).
