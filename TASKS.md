## Phase 2 — Custom slugs, permissions, password gate, QR

- [x] Add `permissions` list + `links.create_custom_slug` enforcement — file(s): api/auth.py, api/links.py — done when: creating a link with a custom slug returns `403` for a user lacking the permission and succeeds for one who has it (or is `admin`) — verified the admin-bypass and 400/409 paths via curl; the true non-admin-without-permission 403 path can't be exercised until Phase 4 ships user management (no way yet to create a restricted user), noted as a follow-up check once that lands
- [x] Add custom-slug validation (charset/length) and collision handling — file(s): api/links.py — done when: invalid custom slugs are rejected with a clear error and slug collisions return a conflict error instead of overwriting an existing link
- [x] Add `password_hash` field to link records + `POST /api/links/{slug}/password` — file(s): api/links.py — done when: an owner/admin can set/change/remove a link's password via this endpoint, stored in the shared `pbkdf2_sha256$...` format — also scrubbed `password_hash` from every API response (`create`/`get`/`list`/`set password` now return a `password_protected` boolean instead)
- [x] Implement password-prompt page in `redirect` (embed + html/template) — file(s): redirect/main.go, redirect/prompt.html, redirect/passwordgate.go — done when: `GET /r/{slug}` for a password-protected link renders the prompt instead of redirecting, with the slug safely escaped
- [x] Implement password verification on `POST /r/{slug}` — file(s): redirect/main.go, redirect/passwordgate.go — done when: correct password redirects (`302`), incorrect password re-renders the prompt with an error (`401`), and every request re-fetches the link fresh from KV (no unlock cookie, per the confirmed re-prompt-every-time decision) — verified cross-language (Python-hashed, Go-verified via stdlib `crypto/pbkdf2`) via curl, including that removing a link's password takes effect on the very next request with zero stale state
- [x] Spike: add `qrcode`/`pypng` deps and confirm componentize-py build still works — file(s): api/pyproject.toml — done when: `uv run componentize-py -w spin:up/http-trigger@4.0.0 componentize app -o app.wasm` succeeds with the new deps and the resulting `.wasm` runs under `spin up` — no Pillow/C-extensions pulled in (confirmed via uv.lock: only `qrcode`, `pypng`, `colorama`, all pure Python)
- [x] Implement `GET /api/links/{slug}/qr` (svg + png, web/print sizes, download) — file(s): api/qr.py, api/app.py, spin.toml — done when: both `format=svg` and `format=png` return valid, scannable QR images at both `size=web` and `size=print`, and `download=1` sets `Content-Disposition` — verified under `spin up`; **note:** added a `public_base_url` Spin variable so the QR encodes the short link (`{public_base_url}/r/{slug}`) rather than the raw `target_url` — encoding the target directly would let a scan bypass the redirect, analytics, and password gate entirely
- [x] End-to-end manual verification of Phase 2 — file(s): (none — verification step) — done when: a permitted user creates a custom-slug, password-protected link; visiting it prompts for a password and only redirects on a correct entry; the QR code for the link scans correctly with a phone camera — verified via curl: created a combined custom-slug + password-protected link, confirmed the password prompt/reject/accept flow and a well-formed QR (visually inspected, encodes the short link per source review — no physical phone/camera available in this environment to scan it)
