How destinations are checked

Every link's destination is checked against this policy when it's created, and again whenever its destination is changed. Precedence is always the same: a deny rule always wins; otherwise an allow rule (or a default of Allow) lets it through; otherwise it's blocked.

A rule matches its host and every subdomain of it, nothing else. A rule for example.com also covers shop.example.com and evil.example.com — but not notexample.com. Scheme, port and path are never part of a rule; only the host is checked.

Two sharp edges worth knowing: an allow rule for a shared-hosting domain (like github.io or s3.amazonaws.com) allows everyone on it, not just the subdomain you meant — the fix is a deny rule for the specific subdomain, which wins. And an exception can't be carved out of a denied tree — a deny rule beats every allow rule beneath it, so if you need "block this domain except for one subdomain," switch the default to Block and enumerate what's allowed instead.
